Stage 1 — net effects

OLS on log1p(outcome) with HC1 robust standard errors and dummy-coded categoricals, plus a VIF collinearity screen. Same formulas as the Python package (the package adds a negative-binomial robustness model).

Stage 2 — predictive importance

Five fixed 80/20 hold-outs; a gradient-boosting model against an OLS baseline; permutation importance (ΔRMSE on the held-out fold) with the elbow screen that selects the Stage-3 conditions.

Stage 3 — configurations (fsQCA)

Direct calibration, necessity analysis, truth table, and Quine–McCluskey minimisation — a line-for-line port of the package engine, differential-tested against it (see Check & scope).

Parity with the mixtriad package (v1.1.2)

stagerelationship to the package
fsQCA (Stage 3)Line-for-line port. Differential-tested against the reference implementation: all 255 three-condition minterm sets minimise identically (with and without remainders); calibration agrees to ≤ 3 × 10⁻¹⁶; on the shipped demo corpus the truth tables, all three solutions, and the necessity tables are identical for both outcome directions.
Regression (Stage 1)Same formulas — OLS on log1p, HC1, normal-based p, VIF. Agrees with statsmodels to ≤ 10⁻¹² on the demo. The package additionally fits the negative-binomial robustness ladder, which the studio omits.
Importance screen (Stage 2)Simplified. A fixed-hyperparameter gradient-boosting model replaces Bayesian-tuned XGBoost, and the train/test shuffle differs from scikit-learn's. Importance rankings and the retained set are typically the same (they are on the demo corpus), but the metrics are not comparable run-for-run. Use the Python package for the analysis of record.

Verifies this browser's copy of the engine against a brute-force minimum-cover oracle and the calibration invariants — the same idea as mixtriad selfcheck.
